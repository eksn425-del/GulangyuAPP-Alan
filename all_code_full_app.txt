1. 项目整体定义
“听见·鼓浪屿”是一个面向视障与行动不便人群的无障碍导览与数字孪生验证系统，当前由两个实际工程共同组成：

- e:\my-gulangyu
  负责 Web 端、AI 对话、建筑内容、数据库、后台管理、路径算法、实验结果展示

- e:\Gulangyu_3D
  负责 Unity 3D 场景、盲杖交互、危险探测、代理实验、A/B 数据生成

两个项目合起来构成的不是单一页面应用，而是一个“用户体验端 + 业务中台 + 仿真实验端”组成的完整 APP 级系统。

================================================================================
2. 项目要解决的问题
================================================================================
当前系统要解决的核心问题有四类：

2.1 真实游客体验问题
- 让用户能够浏览鼓浪屿重点历史建筑
- 让用户通过二维码或纸质地图快速进入对应建筑详情
- 让用户通过语音与 AI 进行问路和导览交互

2.2 无障碍导航问题
- 将鼓浪屿局部建筑与道路信息结构化
- 将坡度、摩擦、路面材质等无障碍因素纳入路线计算
- 用相对方向而不是东南西北，为视障用户生成可执行导航指令

2.3 风险感知与验证问题
- 在 Unity 中模拟视障通行时的盲杖探测
- 把危险区域、跌落点、路面类型触发为可记录事件
- 把仿真数据回流到主业务后端形成分析依据

2.4 展示与验证问题
- 用策展看板直接展示 A/B 实验结果
- 验证 safer 路径与普通路径的风险差异
- 形成“算法 -> 仿真 -> 数据 -> 展示”的闭环

5. 当前端到端业务流
================================================================================
5.1 建筑导览流
1) 用户进入 Web 首页
2) 打开建筑名录或扫码进入指定建筑
3) 前端请求 /api/buildings 或 /api/buildings/{id}
4) 后端从 SQLite 返回建筑内容
5) 前端展示图片、历史、气味、材质、安全信息

5.2 AI 问路流
1) 用户在 AiPage 输入文本或语音
2) 前端收集 user_bearing、message、strategy
3) 后端识别是否是导航意图
4) 后端做地名纠错与起终点提取
5) 后端调用 graph_engine 生成路线
6) 路线结果写入系统 prompt
7) 大模型输出面向用户的自然语言导览回答

5.3 二维码联动流
1) 用户扫描建筑二维码
2) Web 前端识别 URL 中的 id
3) 自动进入对应建筑详情页
4) 若摄像头不可用，可上传二维码截图进行识别

5.4 Unity 风险上报流
1) 玩家或代理在 Unity 场景中移动
2) DigitalCane 或 HazardZone 检测到危险
3) Unity POST /api/record_hazard
4) 主业务后端写入 hazard_logs
5) Web 端后续可读取风险聚合结果

5.5 Unity A/B 实验流
1) Unity 的 ABTestController 生成 A/B 两组代理
2) B 组可通过 /api/route 获取 safer 路径
3) 代理运行中记录 hazard 次数、路径长度、完成时间
4) Unity POST /api/ab_test_summary
5) 主业务后端写入 ab_test_summaries
6) Web 策展看板读取 latest/history 展示实验结果

8. 当前算法体系
================================================================================
8.1 地名识别算法
主后端不是简单关键词匹配，而是多层容错机制组合：
- 别名表匹配
- 拼音全量匹配
- 拼音前缀匹配
- 模糊子串匹配
- 根据 ASR 置信度动态调整阈值

目标是提升真实口语、识别误差、简称表达下的地点识别成功率。

8.2 路径规划算法
核心实现位于 backend/graph_engine.py，当前算法流程为：
1) 从 SQLite 读取节点与道路
2) 用 NetworkX 构建图
3) 用 Haversine 计算边距离
4) 结合 slope、friction 生成权重
5) 使用 shortest_simple_paths 找候选路线
6) 做去重与重叠率过滤
7) 输出路线步骤、距离、转向说明

8.3 权重设计
边权不是单一距离，而是由以下要素混合而成：
- 距离
- 坡度
- 摩擦系数
- 用户类型

用户类型当前包括：
- normal
- elderly
- disabled
- blind

8.4 导航话术生成
大模型不是自由闲聊，而是基于后端先算出的路线结构，再生成面向视障用户的中文播报。
当前话术约束强调：
- 左转
- 右转
- 直行
- 避免使用东南西北

8.5 Unity 风险实验算法
Unity 端的实验不是抽象随机仿真，而是基于：
- 真实场景中的 NavMesh 移动
- 危险区触发
- 盲杖探测
- 路径长度统计
- 完成时间统计
- hazard 次数统计

因此它是“规则驱动 + 场景驱动”的行为实验机制。

11. 当前代码状态中的关键事实
================================================================================
- 前端主界面逻辑大量集中在 src/App.jsx
- AI 对话独立在 src/AiPage.jsx

- Unity 仓库内也保留了一个轻量 Backend，但它不是整个系统的主业务后端
