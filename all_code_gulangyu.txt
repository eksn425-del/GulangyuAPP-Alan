1. 项目目标与系统边界
本项目是面向视障与行动不便人群的无障碍导览系统，采用前后端分离架构：
- 前端：React + Vite（交互界面、语音对话、管理台）
- 后端：FastAPI + SQLite + SQLAlchemy（数据服务、路网算法、AI编排）
- AI：通过 OpenAI 兼容接口调用 DashScope 模型（qwen-turbo / qwen-vl-max）

项目包含 Unity 联动能力（/api/record_hazard、/api/ab_test_summary、/api/hazard_heatmap），用于风险上报、A/B 实验汇总与分析闭环。

5. 核心业务逻辑（可追溯主链）
================================================================================
5.1 AI语音导览链路（/api/chat）
1) 前端 AiPage 发送 message、user_bearing、strategy
2) main.py 进行地名识别：
   - 别名匹配 PLACE_ALIASES
   - 拼音匹配 PLACE_PINYIN / PREFIX
   - 模糊匹配 fuzzy_substring_details
3) 识别出起终点后调用 route_engine.get_safest_route()
4) 将路径步骤注入 system prompt，约束“左转/右转/直行”播报
5) 调用 qwen-turbo 生成回答
6) 返回：
   - reply
   - debug_info（识别地点、分数、strategy、latency_ms）

5.2 路径规划链路（graph_engine.py）
1) 从 SQLite 读取 accessibility_nodes 与 roads 构图
2) 计算边属性：distance（Haversine）、slope、friction
3) 路由策略：
   - shortest：仅 distance 权重（A组）
   - safest：distance + slope + friction（B组）
4) 使用 shortest_simple_paths 取候选路径并去重
5) 输出 steps（转向指令、距离、材质、备注）与总里程

5.3 风险数据链路（Unity/Web -> /api/record_hazard）
1) 客户端上报 hazard_type/obstacle_type + xyz + 时间
2) main.py 写入 SQLAlchemy 表 hazard_logs
3) analysis.py 提供统计输出（/api/stats 消费）

5.4 A/B 实验汇总链路（Unity -> Backend -> Dashboard）
1) Unity 的 ABTestController 按 group_A/group_B 生成 Agent，并分别记录路径长度、完成时长、hazard 次数
2) 实验结束后 POST /api/ab_test_summary，后端写入 ABTestSummary 表
3) 后端在写入与查询 latest/history 时统一计算验收条件：
   - B组危险率 < A组危险率的 70%
   - B组平均路径长度 >= A组平均路径长度
4) 前端 CuratorDashboardSection 拉取 latest/history，在 Dashboard 中展示当前结果与历史趋势
5) 当前已验证一轮真实联调结果：A组危险率 1.0，B组危险率 0.0，且 B 组路径长于 A 组

8. 当前实现注意事项（避免误判）
================================================================================
1) DELETE /api/buildings/{building_id} 当前已整理为单一定义，后续若改权限逻辑只需检查这一处。
2) init_db 在 main.py 中未自动执行，数据库初始化依赖外部脚本/历史数据。
3) /api/route 当前是 GET（不是 POST），测试文档需与实现保持一致。
4) A/B Dashboard 的 latest/history 依赖真实数据库数据；若 Unity 没有成功提交 summary，前端不会显示新结果。
5) 当前 SQLite 中仍保留历史旧实验数据，分析最新实验时应优先以最新 test_run_id 为准。

9. AI 接手修改准则
================================================================================
1) 改路网数据：优先修改 backend/database.py 的节点与道路数据，再重建数据库。
2) 改寻路算法：只改 backend/graph_engine.py，并回归 /api/route。
3) 改AI话术/识别：只改 backend/main.py 的 /api/chat 相关逻辑。
4) 改前端接口行为：同时检查 src/config.js、src/App.jsx、src/AiPage.jsx。
5) 改测试口径：同步更新 evaluate_real_users.py、tst_report.py 与测试手册。
